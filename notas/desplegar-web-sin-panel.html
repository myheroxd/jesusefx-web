Cómo despliego esta web sin entrar en ningún panel

17 de noviembre de 2026 · 5 minutos · revisado el 23 de noviembre

Esta web son ficheros estáticos servidos desde Cloudflare Workers. No hay panel de administración: publico desde la terminal, con un script y un token.

Por qué así

Porque el sitio es HTML y CSS, sin base de datos, y me interesa que cada cambio quede en Git. Subir ficheros por una interfaz web es más lento y más fácil de romper.

La configuración de Workers

{
  "name": "web",
  "compatibility_date": "2026-11-14",
  "assets": {
    "directory": "./public",
    "html_handling": "auto-trailing-slash",
    "not_found_handling": "404-page"
  }
}

Con html_handling en automático, /cv sirve cv.html sin que el usuario vea la extensión. not_found_handling usa mi propio 404.html.

El token

Un token de API con dos permisos: Workers Scripts: Edit y Cache Purge. Nada más. Vive en un fichero con permisos 600 fuera del repositorio, y el script comprueba antes de desplegar que sigue activo:

curl -s -H "Authorization: Bearer $TOKEN" \
  https://api.cloudflare.com/client/v4/user/tokens/verify

El script

Cinco pasos: comprobar credenciales, copiar los ficheros, preparar el paquete, desplegar con Wrangler y sincronizar con GitHub.

npx wrangler deploy
curl -X POST "https://api.cloudflare.com/client/v4/zones/$ZONA/purge_cache" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  --data '{"purge_everything":true}'

El último paso, el de GitHub, ya no usa claves SSH. Desde el 23 de noviembre la autenticación la resuelve gh, que deja a git configurado solo para github.com: el token no se envía a ningún otro servidor y no hay claves que copiar entre equipos.

Los errores que me costaron tiempo

  • Caché de la CDN. El despliegue funcionaba pero seguía viendo el HTML viejo. La purga va ahora dentro del script, no como paso mental.
  • Directorios ocultos. cp * no copia .well-known. Con cp -a "$origen"/. se copia todo, incluido lo que empieza por punto.
  • Errores silenciados. Un | grep ... || true ocultaba que el despliegue había fallado. Ahora, si la comprobación del token falla, el script se para.

Resultado

Publicar es un comando. El script despliega, purga, comprueba las rutas con curl y sube el commit a GitHub con el mismo mensaje. Si algo falla, no hay despliegue a medias: se para antes de tocar producción.
