Cómo entro por SSH a casa sin abrir puertos

17 de noviembre de 2026 · 4 minutos

Mi router no tiene IP fija y no quería abrir el puerto 22 a internet. La solución fue un túnel de Cloudflare con una capa de acceso delante.

El problema

Quería administrar el equipo de casa desde el aula o desde el móvil, sin depender de la red local y sin exponer SSH a cualquiera. Abrir el puerto y confiar en la contraseña no me parecía aceptable, y la IP pública cambia cada cierto tiempo.

La pieza que lo resuelve

cloudflared es un demonio que abre una conexión saliente hacia Cloudflare. El router no necesita ningún puerto abierto: es el equipo de casa el que llama hacia fuera.

cloudflared tunnel create ssh-casa
cloudflared tunnel route dns ssh-casa ssh.jesusefx.es

El túnel se configura con un config.yml que apunta al SSH local:

tunnel: ssh-casa
credentials-file: /home/usuario/.cloudflared/ID.json

ingress:
  - hostname: ssh.jesusefx.es
    service: ssh://localhost:22
  - service: http_status:404

Y como servicio del sistema, para que arranque solo:

sudo cloudflared service install

La capa de acceso

El túnel no basta: si publico SSH tal cual, cualquiera lo alcanza. En Cloudflare Zero Trust creé una aplicación de tipo self-hosted para ssh.jesusefx.es con una política que solo permite mi correo, con código de un solo uso. Quien no esté en la política no llega ni a ver el puerto.

El cliente

En el equipo desde el que me conecto, el bloque de ~/.ssh/config:

Host casa
  HostName ssh.jesusefx.es
  User jesusefx
  ProxyCommand cloudflared access ssh --hostname %h

A partir de ahí, ssh casa y listo, desde cualquier red.

Lo que falló por el camino

  • El servicio del sistema no arrancaba con el fichero de credenciales mal referenciado. Revisar la ruta absoluta fue suficiente.
  • La sesión de Access caduca. Al principio me extrañaba que pidiera el código otra vez; es el comportamiento normal, y se ajusta en la política.
  • Probar el túnel desde la propia red de casa no demuestra nada: hay que hacerlo desde fuera, con datos móviles o desde otro sitio.

Resultado

Un acceso por SSH estable, sin abrir puertos, con autenticación de Cloudflare por delante y sin depender de la IP del router. Para administrar un equipo de casa o un servidor pequeño me parece la opción más limpia que he probado.
